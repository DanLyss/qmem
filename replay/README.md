# qmem-replay

`qmem-replay` исполняет profile без исходного приложения: по расписанию выделяет и освобождает память, заполняет резидентные страницы и касается страниц с заданной частотой. Цель — те же эффекты в ядре, что у оригинала: page faults, RSS, LRU, грязные страницы.

Одна программа на C, только libc, root не нужен. Работает на Linux и на Linux-совместимых ядрах (проверено: x86-64 glibc, HarmonyOS aarch64 musl).

## Запуск

```sh
make                                            # → replay/qmem-replay
replay/qmem-replay profile.txt [--stats stats.csv] [--log run.log [--log-level events|ticks|touches]]
```

| Опция | Что даёт |
| --- | --- |
| `--stats F` | CSV по эпохам: `t_ms,planned,done,lag_ms` |
| `--log F` | пошаговый лог ([формат](../docs/formats/replay_log.md)); пишется после прогона, на тайминг не влияет |
| `--log-level` | `events` (по умолчанию): события и эпохи; `ticks`: плюс каждый тик; `touches`: плюс каждое касание |

Коды выхода: `0` — успех; `1` — ошибка окружения (не открылся файл, не хватило памяти, `mmap`); `2` — неверные аргументы или ошибка в profile (`profile:<строка>: …`).

В конце в stderr — одна строка:

```
replay: epochs=20 planned=2560 done=2560 skipped=0 populated=128 lagged_ticks=0 max_lag_ms=0.8 minflt=346 majflt=2 maxrss_kb=2792 cpu_s=0.04 wall_s=2.00 checksum=a7d00830269aa500
```

| Поле | Что значит |
| --- | --- |
| `epochs` | эпох в profile |
| `planned` | касаний по плану: Σ `rate × dur` по эпохам, округлено вниз в каждой |
| `done` | сделано касаний по отображённым страницам |
| `skipped` | касание пришлось на неотображённую страницу (unmap раньше конца эпохи) |
| `populated` | страниц, записанных `populate` |
| `lagged_ticks` | тиков, не уложившихся в 1 мс, плюс выброшенные |
| `max_lag_ms` | наибольшее опоздание: начала тика или конца тика, вылезшего за свою миллисекунду |
| `minflt`, `majflt` | page faults процесса (без диска / с диском), из `getrusage` |
| `maxrss_kb` | пиковый RSS (`VmHWM` из `/proc/self/status`) |
| `cpu_s`, `wall_s` | время CPU и реальное время прогона |
| `checksum` | отпечаток последовательности страниц; свой в каждом прогоне |

## Вход: profile

Формат — [docs/formats/profile.md](../docs/formats/profile.md). Коротко:

```
qmem-profile 2
meta epoch_ms=100
region id=0 size=1048576 base=0x7f3a00000000        # регион; base — адрес в оригинале
map t=0 region=0 off=0 len=1048576                  # выделить участок
populate t=0 region=0 off=0 len=524288              # записать каждую страницу один раз
epoch t=0                                            # эпоха t … t+dur
access region=0 off=0 len=1048576 rate=5 write=0.3 pattern=roundrobin
unmap t=2000 region=0 off=0 len=1048576             # освободить
```

- `rate` — касаний **одной страницы** в секунду; replay умножает на число страниц участка.
- `access` относится к ближайшей `epoch` выше; `dur` по умолчанию — `epoch_ms`.
- Незнакомый ключ пропускается; незнакомый тип строки — тоже, с одним предупреждением; незнакомый ключ с `!` — ошибка. `threads=` больше не поддерживается и пропускается как незнакомый.
- `kind=file` — ошибка: файловые регионы не поддерживаются.

Все проверки корректности в loader помечены `/* ext */`: profile из builder их всегда проходит, они нужны для ручных и внешних profile. Без них ошибка в profile могла бы тихо испортить память (`mmap` с `MAP_FIXED` за краем региона).

## Как работает

```
main ─▶ load ─▶ prepare ─▶ replay ─▶ --stats / --log / итоговая строка
```

**1. `load` (`loader.c`)** — текст в таблицы `regions`, `events`, `epochs`, `accesses` (`profile.h`). Регионы нумеруются по порядку (`id` = индекс), события не убывают по времени, эпохи растут; `access` принадлежат последней эпохе выше, у каждой эпохи они лежат подряд (`first`, `n`).

**2. `prepare` (`replay.c`)** — один раз до старта:
- `prev` — для каждого `access` такой же участок (регион, `off`, `len`, генератор) в предыдущей эпохе: эпохи режут непрерывную работу программы, `prev` склеивает их обратно;
- `gen->init` — стартовое случайное состояние генератора (цепочка xorshift от текущего времени);
- `memory_prepare` — резерв адресов под регионы (ниже).

**3. `replay` (`replay.c`)** — тики по 1 мс на абсолютных дедлайнах (`clock_nanosleep(TIMER_ABSTIME)`), от 0 до `end_ms` (последнее событие или конец последней эпохи). На каждом тике `t`:

| Шаг | Функция | Что |
| --- | --- | --- |
| 1 | `sleep_until` | ждать `start + t` мс |
| 2 | `end_epoch` | время текущей эпохи вышло — закрыть её (в логе) |
| 3 | `exec_events` | выполнить события с `t_ms ≤ t` (`memory_apply`) |
| 4 | `start_epochs` | начать эпохи с `t_ms ≤ t`; каждому участку — `carry` и состояние генератора от `prev` |
| 5 | `note_lag` | запомнить опоздание начала тика |
| 6 | `exec_tick` | касания тика: `carry += rate × 1 мс`, целая часть — сделать сейчас; страница — `gen->next`, касание — `memory_touch`; раз в 1024 касания участка — проверка дедлайна |
| 7 | `drop_late_ticks` | тик не уложился: недоделанное выбросить, пропустить тики, время которых прошло, записать опоздание |

Тик 1 мс, потому что он должен быть короче шага выборки DAMON (5 мс): при 10 мс касания шли пачкой, и DAMON видел участок вдвое холоднее. Работа, не влезшая в тик, выбрасывается, а не копится, поэтому replay не уплывает по времени: при перегрузке `done < planned`, но `wall_s` равен длине profile.

`carry` и курсор передаются от `prev`, иначе медленный участок в коротких эпохах не набрал бы ни одного касания, а обход каждый раз начинался бы заново.

**Память (`memory.c`).** У каждого региона — адреса `base` и две битовые карты: `mapped` (страница отображена) и `touched` (тронута после отображения, то есть в RAM).

| Действие | Как |
| --- | --- |
| резерв (`memory_prepare`) | `mmap` на `npages + 1` страниц, `PROT_NONE`, без RAM. По адресу оригинала (`base=`, `MAP_FIXED_NOREPLACE`), если свободен; иначе предупреждение и любой адрес. Лишняя страница после региона не даёт ядру склеить соседние регионы в одно отображение |
| `map` | `mmap(MAP_FIXED)` участка с `PROT_READ \| PROT_WRITE` внутри своего резерва |
| `unmap` | тот же участок заново с `PROT_NONE`: RAM отдаётся ядру, адреса остаются за регионом |
| `populate` | одна запись в каждую отображённую и ещё не тронутую страницу (page fault → страница в RAM) |
| касание (`memory_touch`) | не отображена → `skipped`; первое касание после map → запись (чтение дало бы общую нулевую страницу); дальше запись, если постоянная доля страницы `page_fraction` < `write`, иначе чтение. Пишется всегда одна и та же доля `write` страниц, поэтому грязных страниц — столько же |

## Генераторы

Какую страницу участка тронуть следующей; выбирается `pattern=`.

```c
struct generator_ops {
	const char *name;                                    /* значение pattern= */
	const char *stub;                                    /* предупреждение, если заглушка */
	void (*init)(struct access *a, uint64_t r);          /* до старта; r — случайное число */
	void (*epoch)(struct access *a, const struct access *prev);  /* начало эпохи */
	uint64_t (*next)(struct access *a);                  /* номер страницы в участке */
};
```

Состояние генератора хранится в `access` (`cursor`, `rng`).

| `pattern=` | Файл | Как |
| --- | --- | --- |
| `roundrobin` (по умолчанию) | `gen_roundrobin.c` | по кругу со случайной стартовой страницы, через эпохи продолжает с того же места. Каждая страница получает ровно свою долю касаний |
| `random` | `gen_random.c` | равновероятная случайная страница (xorshift64*). При N касаниях на N страниц ~37% страниц не тронуты |
| `poisson` | `gen_random.c` | **заглушка**: как `random`, одно предупреждение |

Новый генератор — файл `gen_<имя>.c` и строка в таблице `generators.c`.

## Ограничения

- **Дедлайн тика проверяется по одному участку** (раз в 1024 его касаний). Если в эпохе много мелких участков, часы не проверяются, лишняя работа не выбрасывается, и replay отстаёт: в `bench/` profile на 0.5 с шёл 17 с (Linux) и 20 с (телефон). Исправление — общий счётчик касаний за тик.
- Только анонимная память.
- Касания идут одним потоком.
- Прогоны не повторяются: старт генераторов случайный, `checksum` свой.
- `planned` округляется вниз в каждой эпохе: у медленных участков `done` бывает больше `planned`.
- `unmap` оставляет на месте участка отображение `PROT_NONE` (у оригинала там дыра): число отображений (VMA) может отличаться.
- Касание всегда в первый байт страницы.
