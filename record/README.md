# qmem-record: что сделано (каркас, record v2)

2026-10-13 · устройство: [docs/skeleton.md](../docs/skeleton.md), раздел 2 · формат записи: [docs/formats/record.md](../docs/formats/record.md)

`qmem-record` записывает, как приложение нагружает память. Код итерации 1 разложен по каркасу: **driver** запускает приложение или подключается к нему, ведёт время записи (ts_ms, метки часов, паузы VM) и вызывает **источники**. Каждый источник пишет в свою подпапку и описывает себя в `record.json`.

Проверено под root с настоящими DAMON и tracefs на WSL2 (ядро 6.18, damo 3.3.0).

## Что лежит в репозитории

| Файл | Что это |
| --- | --- |
| `record/qmem-record.sh` | Driver: опции, подключение к процессу, цикл тиков, остановка, `record.json` |
| `record/lib.sh` | Общее для driver и источников: сообщения, JSON, `now_ms` — единственные часы записи (`mono`, через `python3`) |
| `record/sources/<имя>.sh` | Источники, по файлу на источник |

## Источники

| Источник | Файлы | Что пишет | Статус |
| --- | --- | --- | --- |
| `damon` | `damon/access.csv`, `damon/damon.data` | Псевдочастоты регионов DAMON (через `damo`) | есть |
| `smaps` | `smaps/<ts_ms>.txt` | Копии `/proc/<pid>/smaps` | есть |
| `proc` | `proc/proc.csv` | minflt, majflt, RSS процесса | есть |
| `system` | `system/system.csv` | meminfo, PSI, vmstat | есть |

Статус каждого источника пишется в `record.json`: `ok`, `off` (выключен) или `unavailable` (здесь не работает, с причиной).

### Интерфейс источника

Источник `X` — файл `sources/X.sh` с функциями:

| Функция | Когда | Что делает |
| --- | --- | --- |
| `src_X_check` | до старта | 0 — может работать; иначе недоступен, причина в `SRC_REASON` |
| `src_X_start <pid>` | после запуска приложения | Начать запись; ошибка → источник `unavailable` |
| `src_X_tick <ts_ms>` | каждые `-i` мс | Снимок (только smaps, proc, system) |
| `src_X_stop` | при остановке | Остановить фоновые процессы |
| `src_X_finish` | после остановки всех источников | Довести файлы (damon: `access.csv`) |
| `src_X_manifest` | в конце | Поля источника для `record.json`: `version`, `files`, параметры |

Новый источник — новый файл и его имя в `ALL_SOURCES` в driver.

## Как пользоваться

```sh
./my_app --flag &
sudo record/qmem-record.sh -o out -p $!                        # все источники
sudo record/qmem-record.sh -o out --sources smaps,proc -p 1234 # только часть источников
```

Запись подключается к уже работающему процессу и идёт, пока он не завершится, или до Ctrl+C. Ctrl+C останавливает только запись, процесс продолжает работать.

| Опция | Значение |
| --- | --- |
| `-o <dir>` | Каталог записи (пустой или несуществующий) |
| `-p <pid>` | Процесс, который записываем (обязательно) |
| `-i <ms>` | Период снимков smaps, proc, system (по умолчанию 1000) |
| `--sources <список>` | Включить только эти источники; неизвестное имя — ошибка (код 2) |

damo и остальные источники подключаются к процессу по pid. То, что процесс делал до начала записи, в неё не попадает.

## Тесты

`tests/test_record_*.py`: раскладка v2 и `record.json`, `--sources`, режимы запуска и подключения, остановка (выход, `-d`, Ctrl+C), метки часов и паузы, tracefs. Тесты с настоящими DAMON и tracefs идут под root (`sudo make test`).
