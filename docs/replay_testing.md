# План: проверка replay

2026-10-20 · статус: согласовано (submodule, пороги и pattern=random — как предложено)

Две задачи:

1. **Лог replay и тесты алгоритма.** replay пишет, что он делает по шагам. Тесты по этому логу проверяют, что алгоритм выполняет нужные шаги: события в нужные тики, смена эпох, число касаний, обход страниц, доля записи, сброс опоздавшей работы. Близость к оригиналу здесь не проверяется.
2. **Сравнение с damoLoad.** Нагрузчик memtest из [DanLyss/damoLoad](https://github.com/DanLyss/damoLoad) считаем эталоном. Его конфиг переводим в profile, запускаем memtest и replay и сравниваем их точные логи обращений: сколько раз какая страница тронута в каждом окне времени.

## 1. Лог replay

### 1.1 Что пишется

Новая опция: `qmem-replay profile.txt --log run.log [--log-level events|ticks|touches]`.

Формат тот же, что у profile: одна запись на строку, `тип ключ=значение`. Время — `t_ms` (время profile) или `t_ns` (наносекунды от старта replay, `CLOCK_MONOTONIC`).

| Строка | Уровень | Когда | Ключи |
| --- | --- | --- | --- |
| `start` | все | Перед первым тиком | `regions`, `events`, `epochs`, `end_ms` |
| `region` | все | После резерва | `id`, `pages`, `base` (адрес в этом запуске) |
| `event` | все | Событие применено | `t` (из profile), `tick` (в каком тике применено), `kind`, `region`, `off`, `len`, `pages` (для populate — сколько страниц записано) |
| `epoch` | все | Эпоха началась или закончилась | `t`, `dur`, `idx`, `what=start\|end`, `planned`, `done` (в `end`) |
| `drop` | все | Тик не уложился в дедлайн | `tick`, `skipped_ticks` |
| `tick` | `ticks`, `touches` | Каждый тик с работой | `t`, `epoch`, `access`, `n` (касаний этого access в тике), `carry` |
| `touch` | `touches` | Каждое касание | `t_ns`, `region`, `page`, `op=w\|r\|skip` (`skip` — страница не выделена) |
| `end` | все | В конце | Сводка, как в stderr |

Записи копятся в памяти и пишутся в файл в конце, как в memtest, чтобы запись в лог не мешала таймингу. Без `--log` код лога не выполняется.

### 1.2 Тесты алгоритма (`tests/test_replay_log.py`)

Каждый тест — маленький profile, у которого результат можно посчитать заранее, и проверка по логу.

| Что проверяем | Как |
| --- | --- |
| События по времени | `event` с `t=500` применён в тике 500; порядок как в profile; `map` раньше любого `touch` этой страницы |
| populate | Записано ровно столько страниц, сколько выделено и не тронуто; повторный populate не пишет ничего |
| Границы эпох | Первый `touch` эпохи не раньше `t`, последний не позже `t + dur`; при `dur < epoch_ms` есть пауза до следующей эпохи |
| Число касаний | Сумма `n` за эпоху равна `rate × страниц × dur` (±1); на тике — целая часть с переносом `carry` |
| roundrobin | Страницы идут подряд по кругу; в следующей эпохе тот же участок продолжает с той же страницы; новый участок начинает со случайной, своей в каждом прогоне |
| random | Все страницы в пределах участка; распределение близко к равномерному (хи-квадрат с большим запасом) |
| Доля записи | Первое касание после `map` — `w`; дальше пишется постоянный набор страниц, его доля ≈ `write`; набор не меняется между эпохами |
| unmap | После `unmap` касания этих страниц — `skip`; после повторного `map` первое касание снова `w` |
| Перегрузка | При неподъёмном `rate` есть `drop`; работа за пропущенные тики не выполняется позже; конец по времени не уезжает |
| Несколько участков в эпохе | Касания каждого участка только в его пределах; суммы по участкам независимы |

Без root, без DAMON, каждый тест — доли секунды.

## 2. Сравнение с damoLoad

### 2.1 Что такое memtest

- Конфиг JSON: регионы (`pages`), треки (`region`, `spatial`, `temporal`, `start_sec`, `end_sec`).
- Каждый трек — отдельный поток: с частотой `hz(t)` выбирает страницу по `spatial` и **пишет** в неё.
- Все страницы региона заранее заполнены.
- `gt.log` — каждое обращение: `ts_ns region page`, часы `CLOCK_MONOTONIC`.

В 101 конфиге из `memtest/configs/`:
- типы выбора страниц: `uniform`, `hotspot`, `zipf`, `gaussian`, `sequential`, `all`;
- законы частоты: `const`, `steps`, `square`, `sine`, `ramp`;
- длительность от 10 до 60 с;
- от 1 до 5500 регионов.

### 2.2 Перевод конфига в profile: `tools/memtest2profile.py`

Ключевое наблюдение: у любого `spatial` memtest есть известная вероятность выбора каждой страницы. Значит, ожидаемая частота каждой страницы считается точно:

```
частота страницы p в момент t = Σ по трекам региона:  hz_трека(t) × P_трека(p)
                                (для spatial=all:     hz_трека(t) на каждую страницу)
```

| memtest | profile |
| --- | --- |
| регион `pages=N` | `region size=N×4096`, `map` и `populate` в `t=0` (memtest заполняет заранее) |
| время | эпохи по `--epoch-ms` (по умолчанию 10 мс, чтобы `square` и `sine` не сглаживались); `hz(t)` — среднее по эпохе |
| `P(p)` для `uniform`, `sequential` | `1/N` |
| `P(p)` для `hotspot` | `hot_ratio/n_hot` для горячих, `(1−hot_ratio)/n_cold` для остальных — как в коде memtest |
| `P(p)` для `zipf` | `(1/k^s) / Σ` |
| `P(p)` для `gaussian` | доля нормального распределения в `[p−½, p+½]`, хвосты прижимаются к крайним страницам — как `round` и `clamp` в memtest |
| частота на странице | соседние страницы с одинаковой частотой → одна строка `access` с `rate` на страницу |
| запись | `write=1` (memtest всегда пишет) |
| порядок выбора страниц | `pattern=random` для случайных `spatial`, `roundrobin` для `sequential` и `all` |

Ожидаемое число касаний каждой страницы в каждом окне получается таким же, как у memtest. Отличается только случайный шум выбора.

### 2.3 Прогон и сравнение: `tools/damoload_check.py`

1. Берёт конфиг. При `--duration S` обрезает его до первых S секунд, чтобы прогон был коротким.
2. Строит profile через `memtest2profile.py`.
3. Запускает memtest. Он ждёт Enter, ему подаётся `\n`. На выходе `gt.log`.
4. Запускает `qmem-replay --log-level touches`.
5. Оба лога сводит к таблице «регион × окно (по умолчанию 100 мс) × страница → число обращений». Время memtest отсчитывается от его первого обращения с поправкой на `start_sec` трека.
6. Сравнивает:
   - **сумма по региону в окне:** отклонение в пределах шума Пуассона (`|a − b| ≤ 4√b + 2`);
   - **распределение по страницам за весь прогон:** расстояние полной вариации ≤ порога (по умолчанию 0.05);
   - **общее число обращений:** расхождение ≤ 2%.
7. Печатает отчёт: по каждому региону и окну, где не совпало, и итог «совпало / нет». Код выхода 0 или 1.

В memtest есть детали, которые на сравнение почти не влияют, но я их учту:
- при отставании memtest накапливает не больше 10 интервалов работы, остальное теряет;
- запуск потоков сдвигает старт на миллисекунды. Окна по 100 мс это поглощают.

### 2.4 Тесты (`tests/test_damoload.py`)

- **Перевод конфига, без запуска.** На маленьких конфигах (`uniform`, `hotspot`, `zipf`, `gaussian`, `all`; `const`, `steps`, `square`) частоты страниц в profile равны рассчитанным вручную.
- **Сквозной прогон** 5–6 конфигов из damoLoad, обрезанных до 2–3 с. Набор покрывает все типы `spatial` и `temporal`, несколько треков на регион и несколько регионов. Ожидается «совпало».
- Тесты пропускаются, если damoLoad не найден.

Полный прогон всех 101 конфига (около 30 минут) в `make test` не входит. Он запускается отдельно: `make damoload-check`. Результат — отчёт `docs/damoload_report.md`: какие конфиги совпали, какие нет и почему.

### 2.5 Где взять damoLoad

**Предлагаю git submodule** `third_party/damoLoad`, закреплённый на коммите `83763e9`. Версия фиксирована, сборка — `make -C third_party/damoLoad/memtest`. Другой путь можно задать переменной `QMEM_DAMOLOAD`.

## 3. Что не входит

- Сравнение через DAMON (что DAMON видит у memtest и у replay). Это следующий шаг, если понадобится; DAMON только добавил бы свой шум.
- Многопоточность replay. memtest запускает трек в отдельном потоке, replay однопоточный. Для сравнения числа обращений это не важно, пока replay успевает. Если не успевает, это будет видно в `drop` и в отчёте.

## 4. Шаги (по коммиту на шаг, тесты до кода)

1. Формат лога в `docs/formats/replay_log.md`, тесты лога, `--log` в replay.
2. Тесты алгоритма по логу (1.2); исправления, если тесты что-то найдут.
3. Submodule damoLoad; тесты перевода; `tools/memtest2profile.py`.
4. Тесты сравнения; `tools/damoload_check.py`; сквозные тесты на обрезанных конфигах.
5. Полный прогон 101 конфига → `docs/damoload_report.md`; README.
