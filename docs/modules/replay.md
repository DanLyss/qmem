# qmem-replay — итерация 1

2026-10-09 · черновик · общая схема: [architecture.md](../architecture.md)

В первой итерации `qmem-replay` — небольшая программа на C. Она читает текстовый profile, выделяет анонимные регионы и касается их страниц с заданной интенсивностью по эпохам. Только анонимная память, один поток, никакого управления давлением.

## Интерфейс

```
qmem-replay <profile.txt> [--seed N]
```

В конце программа печатает сводку: сколько касаний было запланировано, сколько выполнено, на сколько отстали от расписания.

## Формат profile

Текст, одна запись на строку:

```
epoch_ms 100
region 0 268435456          # id, размер в байтах
region 1 67108864
epoch 0                     # номер эпохи; начинается в 0 * epoch_ms
access 0 0 4194304 1200     # region, offset, len, касаний страниц в секунду
access 1 0 67108864 50
epoch 1
access 0 0 4194304 1200
```

Пока нет `qmem-profile`, profile пишется руками или генерируется скриптом `tools/mkprofile.py` из `access.csv` и снимков smaps, которые пишет [qmem-record](record.md).

## Как работает

1. Читает profile в память целиком.
2. Выделяет все регионы через `mmap(MAP_PRIVATE | MAP_ANONYMOUS)` при старте и держит их до конца.
3. Для каждой эпохи:
    - для каждой записи `access` делает `rate × epoch_ms / 1000` касаний случайных страниц из `[offset, offset + len)`;
    - касание — запись одного байта в страницу (запись, а не чтение: чтение нетронутой страницы отдаёт общую zero page, и RSS не растёт);
    - ждёт начала следующей эпохи через `clock_nanosleep` до абсолютного времени, чтобы сдвиг не накапливался.
4. Печатает сводку.

Генератор случайных чисел — xorshift с seed, поэтому прогоны повторяемы.

Давление на память в этой итерации задаётся снаружи, например запуском внутри cgroup с лимитом (`systemd-run -p MemoryMax=...`).

## План

- [ ] **P1.** Разбор profile, выделение регионов, цикл эпох, касания, сводка. *Готово:* profile «256 МБ, каждая страница касается за 10 с» даёт RSS около 256 МБ и около 65 536 minor faults (`/usr/bin/time -v`).
- [ ] **P2.** `tools/mkprofile.py`: profile из `access.csv` и smaps. *Готово:* запись тестовой нагрузки → profile → replay; DAMON на replay показывает горячий регион того же размера и интенсивности, что у оригинала.

## Отложено на следующие итерации

- Файловая память, THP, madvise.
- Выделение и освобождение регионов во времени (mmap/munmap по таймлайну).
- Доля записи и чтения.
- Встроенное управление давлением (cgroup, balloon).
- Многопоточность.
- Бинарный формат profile, статистика по эпохам, метки в `trace_marker`.
