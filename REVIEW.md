# Ревью `main`

Начато 2026-10-21. Цель — минимальный рабочий скелет без ненужных фич. По схеме [docs/architecture.png](docs/architecture.png): файлы разбираются по порядку, правки — по запросу.

## Как работаем (договорились 2026-10-23)

- Перед любой правкой — дифф (код, тесты, документы), правка только после «ок».
- Меняется ровно то, что попросили. Всё побочное (что сломается, что станет мёртвым кодом) — отдельным вопросом, а не внутри диффа.

## Что обсудили и решили оставить

- **smaps, а не maps** — нужен Rss для `populate`.
- **Только анонимная память** — replay пока не умеет файловую (`kind=file` — заглушка): нужны файлы-заглушки, page cache, общие страницы.
- **`readers/layout.py`** — единственное место, которое читает `record.json` и знает раскладку записи.
- **Формула `rate = access_rate / 100 / интервал_выборки`** — не «×2»: множитель зависит от настройки DAMON (5 мс → ×2, 10 мс → ×1).
- **Часы:** в `main` — `boot` через `/proc/uptime` (быстро); вариант `mono` — в ветке.
- **replay остаётся на C** (на C++ был бы короче незначительно).
- **Проверки loader остаются**, но помечены `ext`: внутри пайплайна профиль корректен, проверки нужны для внешних и ручных профилей. Без проверок диапазона `mmap(MAP_FIXED)` тихо затёр бы чужую память.
- **generators — отдельные файлы**: значений `pattern` уже несколько, новый генератор = новый файл + строка в таблице.
- **`prepare()` и `prev` остаются**: `carry` и курсор нельзя посчитать заранее (зависят от выкинутых тиков), а связь «кто чьё продолжение» нужна в любом случае.
- **`--stats` остаётся**: короткий отчёт по эпохам для человека, 13 строк.
- **Цепочка случайных чисел в `prepare()` остаётся** (от времени, без seed), а не `getrandom()` в каждом генераторе.

## Выжимка разбора

- **record** (`qmem-record.sh`, 236 строк): опции → обработчик Ctrl+C → какие источники включены → `check` каждого → старт часов (`START_MS`) → старт источников по pid → цикл: пока процесс жив и нет Ctrl+C, раз в `-i` тик `smaps`/`proc`/`system` → `stop` (damon последним) → `finish` (damon: `damo report` → `access.csv`) → `record.json`.
- **`record.json`** пишет driver, кусок каждого источника — его `src_X_manifest`; читает builder (`layout.py`) и тесты.
- **damon.sh**: на время записи часы трассировки — `mono`, потом возвращаются; `damo record <pid>`; остановка `SIGINT`; `normalize` переводит время снимков в `ts` записи.
- **builder**: readers (файлы → объекты) → `model.py` (регионы из smaps; эпохи по 100 мс: каждой — снимок DAMON из её середины, обрезанный по выделенной памяти и привязанный к регионам; дыры DAMON заполняются последним снимком) → оценщики (`lifecycle`: `region`, `map`/`unmap` по разнице соседних снимков; `resident`: `populate` до Rss; `intensity_passthrough`: `epoch`/`access` с `rate`; `write_all`, `timing_roundrobin` — заглушки) → `profile_v2.write` (объекты → текст).
- **`rate`** — касаний на страницу в секунду; сейчас это псевдочастота DAMON (не выше 200 при выборке 5 мс), а не настоящая частота программы.
- **loader** (`load`): строки → токены → `parse_line` по типу (`meta`, `region`, `map/unmap/populate`, `epoch`, `access`, `counter`, незнакомый — предупреждение) → `add_*` в таблицы. Регионы нумеруются по порядку (`id` = индекс), события по неубывающему времени, эпохи по растущему; `access` принадлежит последней эпохе выше; `rate` умножается на число страниц участка; `dur` без значения = `epoch_ms` в конце. Ключ без `!` можно не знать, с `!` — нельзя.
- **replay** (обзорно): `replay.c` — когда и сколько (тики 1 мс на абсолютных дедлайнах, события, эпохи, `carry`, выброс опоздавших тиков), `gen_*.c` — какая страница, `memory.c` — резерв/map/unmap/populate/касание с битовыми картами `mapped`/`touched`, `log.c` — лог.
- **populate** (`resident.py`): на каждом снимке smaps для отображения `need = Rss − уже заполнено`, недостающее — с младших незаполненных адресов, время — середина между снимками; падение Rss ничего не даёт.

## Замечено, но не трогали (кандидаты на потом)

- `populate` выбирает младшие страницы без оглядки на DAMON: в RAM может оказаться больше Rss оригинала (записано в `README.md`).
- Если запись убить `SIGKILL`, часы трассировки системы останутся `mono` (так и случилось после зависших тестов, вернули вручную).
- `damon.sh`: `check` не проверяет `python3`; `DAMON_RC` может быть локальной.
- Пустые `src_X_tick` у нетикающих источников (driver их не вызывает).
- `qmem-record.sh`: `stop.interrupted` дублирует `stop.reason`; `finish` использует только damon.
- `lib.sh`: кривой перенос строк в комментарии к `now_ms`.
- `system.sh`: у полей `meminfo` нет `+ 0`; PSI `avg10` — сглаженное среднее, точнее брать `total`.
- `layout.py`: `param()` не используется; без ключа `sources` в `record.json` — `KeyError` вместо понятной ошибки.
- `readers/damon.py`: `damon.data.kdamonds` не указан в `files` у damon в `record.json`; `access_hz` и `age` не читаются.
- `profile_v2.py`: `Counter` и строки `counter` никто не создаёт.
- Схема: нет стрелки `regions → observations` в блоке `model.py`.
- `lifecycle` ставит unmap посередине между снимками smaps, а `model` обрезает наблюдения по последнему снимку ≤ середины эпохи: в профиле бывают обращения к уже снятой памяти (replay считает их `skipped`).
- `loader.c`: `real()` принимает `nan` и `inf` (`NaN < 0` ложно) — `rate=nan`, `write=nan` проходят.
- `loader.c`: `base=` проверяется, но нигде не хранится; комментарии «for verify» в `add_region` и у `write_layout` в `replay.c` устарели (verify удалён).
- `loader.c`: ключи с `!` никто не пишет (ни builder, ни tools) — механизм только на будущее.
- `loader.c`: номер региона и события обрезаются до 32 бит (`region=4294967296` → 0 и проходит `check_range`).
- `loader.c`: порядок вычисления аргументов `add_region(num(need("id")), num(need("size")), …)` не определён — при нескольких пропущенных ключах неизвестно, о каком сообщение.
- `loader.c`: `counter` — значения не разбираются; незнакомых типов строк запоминается 16, дальше предупреждение на каждой строке.
- `replay.c`: поиск `prev` перебирает все пары соседних эпох (только при загрузке).
- **`replay.c`, ошибка (проверено):** дедлайн в `exec_tick` проверяется по `k` внутри одного `access` (раз в 1024 касания), `k` обнуляется на каждом `access`. 3000 `access` по 1000 касаний за тик — часы не проверяются ни разу, `drop` не срабатывает: профиль на 20 мс шёл 400 мс (`max_lag_ms=366`, `lagged_ticks=0`). Исправление: общий счётчик касаний за тик.
- `replay.c`: файлы `--stats` и `--log` открываются только после прогона — неверный путь теряет результат; `--seed` больше нет, но `planned` по-прежнему округляется вниз по каждой эпохе (у медленных участков `done > planned`).
- `replay.c`: `tick_ms` — константа файла, но всё ещё передаётся аргументом в `exec_tick`; закрытие эпохи в `start_epochs` дублирует `end_epoch` (нужно только для наложенных эпох).
- `memory.c`: unmap оставляет отображение `PROT_NONE` (у оригинала — дыра): число VMA отличается; map поверх отображённого участка молча выбрасывает его содержимое; `set_bits` идёт по одному биту; касание всегда в первый байт страницы; при невыровненном `base=` предупреждение говорит «not free».
- Генераторы: в шапке `gen_random.c` `random` помечен «(STUB)», хотя это полноценный генератор; лишний `#include <stddef.h>` в `gen_*.c`.
- `replay/README.md` устарел: упоминает `exec.c`, `threads`, «random — заглушка».
